| 现象 | 处理 |
|---|---|
| `--selftest` 里单个采集后端偶尔报 `DXGI 未捕获到任何显示器画面 … AccumulatedFrames=0 的空帧` | 显示空闲/熄屏时会出现，**重跑即过**（本轮 9 个命令连跑时遇到一次，紧接着单跑 exit 0）。判读时先重跑一次再当故障 |

## 7. 关键约束（接手时不要踩）

1. **坐标一律物理像素**；DIP 只在 WPF 布局时换算（ADR 0002）。
2. **P/Invoke 全部集中在 `Interop/NativeMethods*.cs`**，业务代码不直接 DllImport。
3. **贴图窗口是原生分层窗口**（`UpdateLayeredWindow`），不要换成 WPF `AllowsTransparency`（ADR 0003）。
4. **单一数据源**：动作只在 `HotkeyCatalog` 声明、配置项只在 `SettingsSchema` 声明；
   `--selftest` 会校验"表 ↔ 实现"双向一致 —— 加配置项时**必须**同时改 `AppSettings` 与 `SettingsSchema`，
   否则自检立刻报错（这是护栏，不是麻烦）。
5. **橡皮擦只擦标注层**（底图不能被打洞）；**马赛克/模糊作用于当前可见画面**。
6. **不要用 PowerShell 的 `Set-Content`/`Out-File` 写源码文件**：本机 Windows PowerShell 会按 ANSI 写出，
   已把 `SelfTestRunner.cs` 写坏过一次（UTF-8 → GBK → 乱码）。请用编辑器/IDE，或
   `[IO.File]::WriteAllText($p,$t,(New-Object Text.UTF8Encoding($false)))`。
7. **异步代码不要在 WPF UI 线程上阻塞等待**：`--update-test` 曾因 `async` + `GetAwaiter().GetResult()`
   在 UI 线程上**静默挂死 10 分钟**（进程不崩、不报错）。`UpdateService` 现已全部 `ConfigureAwait(false)`，
   且该自检整体跑在线程池上；`UpdateCoordinator` 还把检查/下载整个丢到线程池并带 30 s 超时。
   在 UI 线程上等待异步结果时用 `--settings-test` 里的 `AwaitWithPump`（边抽 Dispatcher 边等 + 超时），
   **不要**写 `GetAwaiter().GetResult()`。
8. **WinExe 的退出码必须用 `Start-Process -Wait -PassThru` 拿**；直接 `& exe --args` PowerShell 不会等待，
   会读到上一次的旧报告文件（我踩过）。
9. **`.iss` 必须保持 UTF-8 **带 BOM**（Inno 读中文串需要），`build-installer.ps1` 会自动补；
   脚本本身必须 ASCII-only（Windows PowerShell 5.1 会把无 BOM 的 .ps1 当 ANSI 读）。
10. **安装包输出目录只保留当前版本**（脚本已加清理）：混着旧版本是分发拿错文件的最快捷径。
11. **未处理异常只在"真实界面事件"里才会进 `DispatcherUnhandledException`**：实测两次
    `Dispatcher.InvokeAsync(... => throw ...)` 的回调异常被 WPF **静默吞掉**（进程不崩、处理器不触发、
    日志里什么都没有），而在 `Window.Loaded` 这类真实界面事件里抛就会正常触发。
    要验证崩溃链路请用 `--crash-now`（它走的就是界面事件这条路）；也不要以为"异常没记录=没崩"。
12. **脱敏要覆盖多种写法**：`settings.json` 里的路径是 JSON 转义（`C:\\Users\\x`）、file:// URL 是正斜杠
    （`C:/Users/x`），只替换"原样路径"会漏。`CrashHandler.Redact` 已处理三种，加新的文本来源时照此对齐。
13. **打包/压缩一律丢线程池**：日志可能上百 KB、压缩是同步 IO，诊断包导出走 `Task.Run`，
    界面线程只显示结果（与第 7 条同源）。
14. **性能埋点的计时边界要卡准**（否则数字好看但没意义）："确认 → 剪贴板可粘贴"的终点必须在
    **真正写入剪贴板成功之后**（起点含裁剪），选保存/贴图时要**取消**这条起点；
    鼠标跟随是**每次移动都记一条**的密集样本，只能进内存（上限 200 条），**绝不要写日志**；
    指标落盘按**指标合并**，否则跑一次自检就把上次真实运行的冷启动数字冲掉。
15. **签名的顺序不能调**：`-Sign` 必须**先签 payload 再 ISCC**（否则装到磁盘的 `WhSnap.exe` 仍是未签名），
    然后签 setup、导出 `.cer`，**最后**才生成 `update.json`（清单哈希必须对应签名后的文件）。
    判断签名好不好看 `Get-AuthenticodeSignature`：自签名在没导入信任的机器上就是 `UnknownError`
    （"terminated in a root certificate which is not trusted"），这是**预期**；`HashMismatch` / `NotSigned` 才是故障。
16. **`--power-test` 是"投递电源消息"，不是真睡眠**：它把 `WM_POWERBROADCAST` 发给程序自己的热键消息窗口
    （与系统广播走同一窗口过程），断言重注册后热键仍被本进程持有、按键仍能派发。别把它的绿灯读成
    "真机睡眠唤醒已验证"；也别为了"更真实"改成 `HWND_BROADCAST`——那等于把假的恢复通知撒给桌面上所有程序。
