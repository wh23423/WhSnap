# ADR 0002：领域层坐标一律物理像素

- 状态：已采纳（M0）
- 日期：2026-10-15

## 背景

混合 DPI 多屏（例如左屏 100% + 右屏 150%）下，"选区错位"是这类工具最常见的翻车点（风险 R1）。
根因几乎都是把 WPF 的 DIP（逻辑像素）与物理像素混在一层里换算。

## 决策

`WhSnap.Core` 的几何类型（`PhysicalRect` / `PhysicalPoint` / `MonitorInfo` / `VirtualDesktop`）
**全部是物理像素**，并且以**虚拟桌面绝对坐标**为唯一口径：

- 采集：整张虚拟桌面位图（原点 `VirtualBounds.X/Y`，可能为负）。
- 选区：绝对物理像素；每台显示器一个遮罩窗口，本屏渲染时先求交再换算成窗口局部坐标。
- 贴图：位置、尺寸、缩放后的显示区域同样是绝对物理像素。
- 导出/裁剪：物理像素 1:1，链路上不允许出现任何 DPI 缩放。

DIP 换算只允许出现在两个地方：WPF 布局（`DpiMath.PxToDip`）与原生窗口落位之后的渲染细节。

## 代价与后果

- WPF 控件里每次定位都要显式换算，代码略啰嗦（`OverlayWindow.PhysicalToDip`）。
- 反过来换来的是：多屏 + 混合 DPI + 竖屏旋转 + 跨屏框选全部走同一套算术，单测能覆盖。
- 单测里可以直接构造"左屏 1280×1024@100% + 右屏 1920×1024@150%、虚拟桌面原点为负"的合成拓扑。
