# ADR 0006：热键统一模型 + 三层冲突检测，不做占用者反查

- 状态：已采纳（M3）
- 日期：2026-10-15

## 背景

规划 §5.7 把"快捷键设置 + 三层冲突检测"列为核心四项之一。
两个现实约束：

1. Windows **没有公开 API 能反查某个热键被哪个进程注册**（`RegisterHotKey` 只返回 1409）；
2. 程序里有三种完全不同的按键：全局热键（`RegisterHotKey`）、遮罩窗口内按键、贴图窗口内按键。

## 决策

**统一模型**：`HotkeyCatalog`（23 个动作 × 3 个作用域）是唯一数据源；
`HotkeyBinding { ActionId, Keys, Enabled }`；`HotkeyBindings.Resolve/Match` 负责解析与派发。
遮罩（`OverlaySession.HandleKey`）与贴图窗口（`PinWindow.HandleKey`）都走 `Match(...)` 派发，
只有"方向键微调""+/- 缩放""Esc 隐藏"这类固定交互写死在窗口里。

**三层检测**：

| 层 | 做法 | 是否阻断 |
|---|---|---|
| L1 系统占用 | **临时释放自己已注册的键 → 逐个试注册 → 再恢复**（`HotkeyManager.ProbeAll`）。试注册成功=可用，失败=占用 | 不阻断，但界面标红 |
| L2 内部重复 | 修饰键规范化后比对，**只在同一作用域内**算冲突 | **阻断**：弹窗让用户选择（撤销 / 仍保存但停用 / 仍保存） |
| L3 常见冲突源 | 内置 19 条已知冲突源表（系统截图、Xbox Game Bar、输入法、微信/QQ、NVIDIA、PowerToys、Snipaste…）+ 12 条保留键 | 只提示，含排查建议 |

冲突策略可配（`block` / `save-disabled`），但**任何情况下都不会静默失败**。

## 代价与后果

- L1 探针会短暂注销再注册自己的热键（毫秒级），因此只在"打开设置/改键/点检测"时跑，不常驻。
- L3 是启发式：表要随 Windows 版本与常见软件更新维护（表在 `KnownConflictSources`，加一行即可）。
- 低级键盘钩子降级路径**明确不实现**（风险与杀软误报），放 backlog。

## 重新评估的时机

- 如果微软将来开放热键占用者查询 API，L3 可以升级为精确判定。
- 如果用户强烈要求"被占用的键也要能用"，再单独设计钩子方案的开关与风险提示。
