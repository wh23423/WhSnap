**首次 CI 失败的真因与修法**（run `38787260317`，值得记住）：
`release.yml` 用**数组 splat** 传参：`$buildArgs += @('-Version', $v)` … `./build-installer.ps1 @buildArgs`。
在 GitHub Actions 的 `pwsh` 7 wrapper 下，`-Version` 被绑到了 `$Configuration`、版本串落到了 `$Runtime`，
于是 `dotnet publish` 收到一个名为 `1.0.0-preview.2` 的 RuntimeIdentifier →
`error NETSDK1083`。日志里的 `==> Publishing -Version / 1.0.0-preview.2` 就是铁证。
**本机无法复现**：本机只有 Windows PowerShell 5.1（没有 `pwsh`）。
已改为 **hashtable splat**（`$buildArgs = @{ Version = … }` / `$buildArgs.Sign = $true`），
显式命名绑定，两版 PowerShell 行为一致；本机回归：旧写法 `BINDING_BROKEN`、新写法 `BINDING_OK`。
**教训：改 `.github/workflows/*.yml` 的 pwsh 脚本时，别指望本机 5.1 能复现——优先用 hashtable splat。**

**顺手修掉的两个真缺陷**（构建期查不出来，只能靠渲染/运行发现）

   现在隐式文本样式不写死前景色，改为继承最近控件的前景（无控件祖先时回落 `OnDark`）。

   （`GridLength` 不接受资源里的 `double`）。已改为 `GridLength` 令牌（`Focal.TitleBarHeightLength` 等）。
