## 延后（v1.1 或按需）

| 项 | 为什么先不做 | 备注 |
|---|---|---|
| **Focal UI 落地时留下的设计边界**（见下） | 都是"设计稿与现有模型之间的落差"，改动会动到 Core 数据模型，值得单独一轮 | 来源：M7 UI 落地 |
| **低级键盘钩子降级（`WH_KEYBOARD_LL`）** | 有全局性风险（影响系统输入延迟、易被杀软误报），且必须给用户明确风险提示；当前"改键"已能解决冲突 | 规划 §5.7 的降级路径，仍会做，但要单独设计开关与提示 |
| 历史记录回放（`,` / `.` 翻看上一次次截图） | 自用价值不低，但不属于"核心四项" | 规划 §12 第 2 项，可能提前 |
| 贴图分组 | 需要面板与层级模型扩展 | v1.1 |
| GIF 动图贴图（含帧步进） | 需要 WIC/GIF 解码 + 帧调度，工作量不小 | v1.1 |
| 贴图缩略图列表/常驻面板 | 当前管理面板已够用 | 视使用频率 |
| 主题色/界面字体深度自定义 | 外观项，不影响功能 | v1.1（先浅色/深色） |
| 完整 HTML 排版渲染 | 需要引入 IE/WebView 引擎，重量与攻击面都远超收益 | **明确不做**，只做纯文本提取 |
| OCR、录屏、云同步、图床、便携版 | 规划 §2.3 写死的边界 | **不做** |

## Focal UI 落地留下的设计边界（M7）

| 项 | 现状 | 说明 |
|---|---|---|
| 标注图元的独立不透明度 | 「不透明度」滑杆映射到已有的 `AnnotationStyle.FillOpacity`（形状=填充浓度，马克笔/高亮=笔迹 alpha） | 设计稿想要"整图元 alpha"，需要给 Core 的 `AnnotationStyle` 加字段 + 命令栈/合成管线跟进 |
| 标注选中手柄 4 向 vs 设计稿 8 向 | 只画 4 个角 | `AnnotationEditing.Resize` 只支持四角与内部拖动；画 8 向会造出"抓不动的假手柄"，宁缺毋滥 |
| 图标虚线子路径 | `capture` / `select` / `flipH` / `flipV` 的 `stroke-dasharray` 画成实线 | WPF 单个 `Geometry` 无法逐子路径设 `StrokeDashArray`；要还原需拆成两个几何键 |
| `droplet` 的半透明填充子路径 | 画成纯描边 | 设计规则是"不允许双色图标"，填充档需要单独的设计裁决 |
| 设置 / 贴图面板的第三个窗口按钮（最大化） | 只做了最小化 + 关闭 | `WindowStyle=None` 下 WPF 最大化会盖住任务栏，需要引入 `WindowChrome` 或处理 `WM_GETMINMAXINFO` |
| 首次向导的三步翻页 | 单页 + 3 段进度（与设计稿一致） | 若要真正的分页，需要状态机改造 |
| 首次向导的 L1 系统热键占用提示 | 只做窗口内的内部撞键与保留键校验 | 宿主已有注册探针，接 `ShowHostStatus()` 即可回注（当前未接） |
